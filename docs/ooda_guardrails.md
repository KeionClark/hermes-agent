# OODA P3a guarded admission (dark only)

`hermes_cli.ooda_controller.run_once` is an opt-in, finite consumer; it is not installed as a scheduler, subscriber, deployment hook, or customer workflow. No canonical board is migrated by this change. Before invoking it on a fresh disposable board, explicitly migrate the event bus, goal metrics, outcome ledger, and guardrail schema. A missing guardrail policy or schema fails before subscriber registration. Do not copy synthetic test approvals or architecture budget examples into live configuration.

The caller supplies `GuardrailPolicy` with a verified price per million tokens (Decimal/string), estimated positive tokens, agent/lane IDs, an independently approved scope reference, and *all four* caps: `task_token` (tokens), `agent_day`, `lane_week`, `global_day` (USD). The four caps are tested under the controller's existing `BEGIN IMMEDIATE`; the reservation key is the investigation idempotency key. Price and caps are not inferred from model names or assistant reports. Spending and increased commitments require Keion's decision under the operating policy. `guardrails_enabled=False` is only for explicitly identified legacy dark test fixtures, never a production invocation.

For each verified gap, under one board write transaction, the controller checks active capacity and rights, assesses the seven-day evaluated outcome ledger drift (insufficient evidence is unknown, not zero risk), checks an optional independent secondary goal trip-wire from stored measurement provenance, reserves, inserts the card and ACKs the event. Failed reservation or assessment persists a deduplicated agent safe halt, returns without ACK or card, and breaks the batch to avoid replay storms. A failed insert rolls back the reservation and event ACK before the halt is recorded. The outstanding estimate remains reserved until an *external trusted usage source* calls `commit_act` with actual tokens, or `release_act` when no action occurred; the controller does not invent actual usage from `run.completed`. Reset is explicit via `reset_guardrail(scope, actor, reason, approval_ref, now)` and retains spend history.

The optional trip-wire binds a primary evaluated outcome to the event goal, a secondary goal and stored baseline, and retrieves the latest secondary measurement at decision time. Sources must be independently identified, baseline/latest versions equal and non-null; unknown/stale readings fail closed. Drift/trip-wire trips return a structured, inert `RollbackProposal` in `OodaResult.rollback_proposals` alongside a durable halt. No git revert, deploy, release, archive or customer send follows from a proposal. A reviewer must evaluate it separately.

No scheduled or route adapter invokes `ooda_controller.run_once` in this tree; the similarly named `kanban_event_router.run_once` is separate. Before any activation, independently QA the exact revision, cap/price authority, pending event recovery, usage reconciliation and ordered release checks; obtain an explicit live authorization route rather than treating these dark tests as approval.
